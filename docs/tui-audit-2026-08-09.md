# Corvus TUI 体验审计与修复范围

日期：2026-08-09

## 结论

当前 TUI 的主要问题不是单一配色，而是渲染器没有共享同一套宽度和高度预算。滚动条、transcript、弹层、composer 与状态栏分别计算尺寸；正常终端会出现右侧孤立字符和多余空行，窄终端则会裁切交互控件或丢失底部状态。

本次已实际测试 `110x48`、`80x30`、`60x20`、`60x12`、`50x16`、`40x14` 和 `36x14`，覆盖 `/help`、`/status`、`/skills`、工具输出、审批、滚动、resize、队列输入和 modal 粘贴。写入探针均被拒绝，审计过程没有创建项目文件。

## P0：布局与交互

### 1. Transcript 宽度与滚动条宽度不一致

- alt-screen 为 scrollbar 保留 `W-1` 列，但 user bubble、reasoning 与 tool card 仍按完整 `W` 渲染。
- turn separator 同样按 `W` 生成；从 80 列缩到 40 列后会被折成多行。
- `transcriptSourceFixed` 在 resize 时不重新渲染，因此旧尺寸的 separator 会永久保留。

根因：`internal/cli/chat_tui.go` 的 `transcriptContentWidth` 与 `internal/cli/transcript.go` 的 `renderTranscriptSource`、`reflowTranscript` 没有使用同一个内容宽度。

修复契约：alt-screen 下所有 transcript source、separator 和 wrapper 只能使用 `transcriptContentWidth`；resize 后所有依赖宽度的 source 都要重新生成。

### 2. 短屏弹层没有总高度预算

- `36x14` 的 skills manager 显示不到任何技能条目，搜索框和 footer 被裁切。
- `40x14` 的 approval 会隐藏拒绝提示、快捷键或底部状态。
- manager、cheatsheet 等仍强制最小 40 列，实际窗口更窄时会超出画布。

根因：skill visible row 数有硬性下限，manager card 只在最后被截断；bottom panel 将全部内容相加，而不是在渲染前按剩余高度限制列表。

修复契约：弹层先取得可用的宽度和高度预算，再决定可见行数与紧凑 footer。小于 40 列时不得绘制超出画布的行；高度不足时至少保留标题、当前选择、一个操作入口和退出提示。

### 3. Completion 关闭后保留无意义空白

- 打开 `/` completion 后按 Esc，`composerRaisedRows` 会一直保留到下一次非空提交。
- 在 `60x12` 中会留下大面积空白，严重压缩 transcript。

根因：raised composer 的“菜单关闭后不下落”策略没有考虑屏幕高度与 popup 已关闭的状态。

修复契约：关闭 transient panel 后立即释放其 raised rows；只有仍然可见的 persistent panel 才能占用底部预算。

### 4. 运行中反馈队列会突破底部高度

- queue indicator 在 `View()` 中渲染到 composer 上方，但未计入 `bottomRows()`。
- 运行状态文字换行时，光标 Y 坐标只增加一行。

根因：渲染顺序与高度预测分离，queue 与 wrapped working line 没有进入同一预算函数。

修复契约：`bottomRows()` 与 `View()` 共享所有可见底部行的行数，包括 queue indicator 与 wrapped working line；光标原点使用同一计数。

### 5. Modal 打开时粘贴会写入隐藏 composer

- 在 `/skills`、MCP、approval 或 quick picker 中粘贴，内容会进入隐藏输入框。
- 关闭弹层后 draft 才出现，可能导致误提交；quick picker 搜索框也收不到粘贴。

根因：`tea.PasteMsg` 在 modal 路由之前无条件交给 textarea。

修复契约：modal 是唯一焦点拥有者。它若支持搜索则接收粘贴，否则丢弃该粘贴并保留隐藏 composer 原值。

## P1：状态正确性与窄屏渲染

- 并行工具在收到无关事件时可能被提前收敛并显示成功；后到失败结果无法修正。
- native scrollback 中无 stdout 的成功 shell 命令只有 dispatch，没有 `✓` 或耗时。
- 窄终端 GFM table 的最小列宽总和可以超过 renderer 宽度。
- Ctrl+B 展开工具输出时，超长单行被静默截断，没有换行或截断提示。
- CJK/emoji 前的 tab 按 rune 而不是 terminal cell 计算，diff 背景条会错位。
- skill detail 的滚轮可以把选中 action 移出真实动作列表，导致没有高亮。

## 新增问题：composer 与历史 user message 的灰色整行背景

### 现象

- 输入框背景持续是水泥灰色，视觉上像固定卡片，和 transcript 底色割裂。
- 历史中用户输入也被画成整块灰色背景，还额外占用上下 padding 行，使长会话显得松散且笨重。

### 根因

- `renderComposerField` 会为每一行 composer 打开 `inputBoxBG`，并将右侧 padding 也染色。
- `renderUserBubble` 会为每条用户消息画完整背景行、内容行和背景行，并填充到整行宽度。

### 修复契约

- composer 改为透明的无边框文本区，保留 textarea 的光标、选择反白和模式 badge。
- user message 改为单行 `›` 文本，不再绘制背景块或上下 padding；当前消息维持 accent，历史消息维持较弱的前景色。

## 修复结果

### 宽度、transcript 与配色

- alt-screen transcript、separator、reasoning、tool card 和 explorer card 统一使用 `W-1` 内容宽度；resize 会重新生成依赖宽度的分隔线。
- composer 取消 `inputBoxBG` 的整行填充；历史 user message 改为无背景、无上下 padding 的 `›` 行，保留当前消息强调色与历史消息弱化前景色。
- 窄屏 Markdown table 采用 stacked fallback；CJK/emoji tab stop 与 completion 的 ANSI 宽度截断已覆盖。

### 高度预算与短屏交互

- completion、queued feedback 与 persistent todo 现在共享 `interactivePanelBudget`。它先固定状态区、composer 和一行 transcript，再保留每个活跃面板的最小可用行，并优先把额外行给正在操作的 completion。
- `40x14` 下 12 条 queue、8 条 todo 和 8 个 completion 候选可同时渲染为精确 14 行；当前编辑 queue、当前 completion 选择和 `Esc` 均保留。
- `40x8` 下背景 todo 自动收起，completion 与退出提示仍可用；仍有空间时会保留当前 queue 项。
- todo 面板按照最终 Lipgloss 渲染后的视觉行数裁剪，已计入顶部边框、长文本换行、活动项窗口与 `+N more` 行。
- skills、cheatsheet、approval、clear confirm 与 MCP 的 list/detail/tools 都取消了 40 列强制最小宽度，并在短屏保留当前选择和退出路径。

### 输出与状态正确性

- completion 关闭立即释放 transient composer raise；modal paste 由可搜索弹层独占，其他隐藏 composer 的弹层会吞掉粘贴。
- 工具 progress 改为按 tool ID 隔离，避免交错事件污染另一工具的 live tail。
- Ctrl+B 的展开工具输出同时限制逻辑行和视觉行。32 KiB 无换行输出在窄屏最多 200 个视觉行，截断提示也会按 gutter 正确收窄。
- Ctrl+B 在调用 ANSI wrap 前先限制超大单行的源片段；1 MiB 无换行输出的渲染分配受 1 MiB 回归阈值约束，不会随着完整源行继续增长。
- queue preview 按实际编号前缀宽度计算可用文本宽度，`[1000]` 等四位编号在 40 列窗口不再折成第二行。
- native scrollback 的静默 shell outcome、长输出、reasoning/tool card reflow 与 queue 编辑窗口均有回归覆盖。
- `Explored` 的连续 read/fetch 子项改为真正嵌套的 `├`/`└` 树；子项文本比标题再右移，避免纯空格 continuation 看起来像 transcript 同级条目。
- 应用内 Ctrl+C/右键复制会保留 `Explored` 的前导空格和树形符号，同时去除 ANSI 颜色码；外部 Markdown 渲染器的空白折叠或非 UTF-8 终端的字符转码不在剪贴板文本层面隐式改写。

## 最终验证

自动验证：

```bash
gofmt -w internal/cli/chat_tui.go internal/cli/chat_tui_test.go internal/cli/complete.go internal/cli/toolcard.go internal/cli/chat_render_test.go
git diff --check
go test ./internal/cli -count=1
go build -o /tmp/corvus-tui-audit ./cmd/corvus
```

结果：`git diff --check` 无输出；CLI 测试通过；审计二进制构建通过。

项目级基线说明：

- `go test ./... -count=1` 已执行。`internal/cli` 通过，但全仓仍有两项与本次 TUI 改动无关的既有失败：`internal/config` 的 `TestLoadCCSwitchLegacyConfigPrefersCorvusFlag` 对已排序 map 的结果断言了相反顺序；`internal/plugin` 的 `TestExamplePluginEndToEnd` 依赖仓库中不存在的 `cmd/corvus-plugin-example` 示例程序。
- 本次没有修改 `internal/config`、`internal/plugin`、`cmd` 或 `go.mod`；上述问题不计入 TUI 验收，需作为独立维护项处理。

实际 TUI 复测（最新二进制）：

- `36x14`：`/skills` 移到第 8 个 skill 后，选中项、`Esc` 与紧凑 footer 均可见；`?` 和 `/` completion 也保持完整退出提示。
- `40x14`：`/mcp` 空状态 manager 的标题、正文与 `Esc` 均在画布内；自动化 fixture 同时覆盖 MCP list/detail/tools 的选择与溢出提示。
- `80x30`：审计期间完成只读会话、resize、历史 user message、tool/reasoning card 检查；composer 与用户历史均无整行灰色背景。
- 组合布局由自动化回归覆盖：`40x14` queue + todo + completion、`40x8` 降级、`40x14` 长 todo 文本、`W=10` 超长工具输出。

## 验收标准

1. 任意 alt-screen 宽度下，最终 `View()` 的每行可见 cell 宽度不超过终端宽度，且总行数等于终端高度。
2. 在 `40x14`，approval 和 skills 至少可见当前选择与退出路径，不得裁掉画布外。
3. completion 关闭后，composer 回到底部，不留下 transient 空白。
4. modal 打开时粘贴不改变隐藏 draft。
5. 彩色模式下 composer 和 user message 不再使用整行背景填充。
6. `go test ./internal/cli -count=1` 通过，并补充上述回归测试。
