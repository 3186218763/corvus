# Corvus

Corvus is a single static binary (Go, `CGO_ENABLED=0`) agent harness for coding
tasks: it drives a provider model through a tool loop — files, shell, search,
LSP, MCP plugins, skills, subagents, compaction — with an event-sourced session
log, an interactive CLI, and an MCP server entry point.

## Build & test

```sh
make build          # CGO_ENABLED=0 static binary -> bin/corvus
make check          # vet + gofmt + catalog-doc freshness + tests + race
make tool-catalog   # regenerate docs/tool-catalog.md
make event-map      # regenerate docs/event-map.md
```

CI mirrors `make check` (`.github/workflows/ci.yml`).

## Architecture at a glance

- `internal/agent` — the run loop, turn state machine, session persistence
  (append/replace event log), compaction, subagents, guards and recovery.
- `internal/boot` — assembly: config → provider, tools, plugins, skills,
  subagents, hooks, prompt construction.
- `internal/tool` — the `Tool` interface, registry, and built-in tool
  capabilities (`ReadOnly`, `Previewer`, `ConcurrencySafe`, `PlanModeClassifier`,
  `SnipHinter`).
- `internal/plugin` — the MCP client (stdio / Streamable HTTP / SSE), adapting
  external servers to the same `tool.Tool` interface.
- `internal/compaction` — pure compaction policy + the `Summarizer` seam.
- `internal/spill` — oversized tool-output persistence seam (session-scoped
  files with a model-facing locator instead of irreversible truncation).
- `internal/store` — the single authority for the on-disk persistence layout.
- `internal/hook` — Claude-compatible shell hooks with a JSONL audit sidecar.
- `internal/event` — the typed event stream every frontend consumes.
- `internal/control` — the interactive controller (CLI/TUI glue).
- `cmd/` — `corvus`, `corvus-exec`, `corvus-mcp-server`, `corvus-catalog`.

## Session model

A session is an append-only event log (`<id>.events.jsonl`) plus an anchor
transcript; model history is derived from the log, never stored separately.
See `internal/agent/session_events.go` (replay limits, torn-tail salvage,
log compaction) and ADR-0006 for the durability tiers.

## Documentation conventions

- `docs/adr/` — architecture decision records.
- `docs/notes/` — research and comparison notes.
- `docs/tool-catalog.md` and `docs/event-map.md` are generated by
  `cmd/corvus-catalog`; `make verify-catalog` (in `make check` and CI) fails
  when they are stale.
